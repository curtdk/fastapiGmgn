# /trade 页面 — 用户列表数据流程

## 一、概述

`/trade` 页面用户列表由**两条路径**协作驱动：

1. **初始加载**：`startMonitor()` 时调用 `GET /admin/api/users` 一次性获取
2. **实时更新**：每笔交易处理完毕后，`_calculate_index()` 广播 `user_status` WS 消息，前端增量更新

前端维护 `userData` 对象（`{address: {...}}`），两路径共用同一数据结构，WS 推送直接覆盖/新增。

---

## 二、初始加载 — `GET /admin/api/users?mint=xxx`

### 位置

[`app/routes/trades.py#L307`](../app/routes/trades.py#L307)

### 获取逻辑

```
SCAN user:* 遍历 Redis 中所有用户 key
  → 对每个 user:{address} 执行 hgetall
  → 检查是否有任何 key 以 "{mint}_" 开头
  → 有 → 该地址属于当前 mint 的用户
  → 读取 cluster_name → 从簇组 Redis 获取最新 cluster_type
  → 返回
```

### 关键判断条件

```python
has_mint = any(k.startswith(f"{mint}_") for k in decoded.keys())
```

只要 `user:{address}` 中存在 `{mint}_holdingQty`、`{mint}_holdingCost`、`{mint}_avgPrice` 等字段，就算该 mint 的用户。

### 返回字段

| 字段 | 来源 | 说明 |
|------|------|------|
| `address` | key 去掉 `user:` 前缀 | 钱包地址 |
| `status` | `user:{address}.status` | dealer / retail / unknown |
| `status_source` | `user:{address}.status_source` | system / manual |
| `conditions` | `user:{address}.conditions` | 判定条件列表 JSON |
| `cluster_name` | `user:{address}.cluster_name` | 所属簇组名称 |
| `cluster_type` | 从簇组 Redis 实时读取 | 最新簇组类型 |
| `cluster_tx_count` | 从簇组 Redis 实时读取 | 簇组总 Tx 数 |
| `cluster_user_count` | 从簇组 Redis 实时读取 | 簇组总用户数 |
| `holding_qty` | `user:{address}.{mint}_holdingQty` | 当前持仓数量 |
| `holding_cost` | `user:{address}.{mint}_holdingCost` | 当前持仓成本(SOL) |

### 前端调用

[`app/templates/trade_live.html#L1091`](../app/templates/trade_live.html#L1091)

```javascript
async function fetchUsers() {
  const resp = await fetch('/admin/api/users?mint=' + currentMint);
  const data = await resp.json();
  userData = {};
  data.users.forEach(function(u) { userData[u.address] = u; });
  renderUserTable();
}
```

## 三、实时更新 — WS `user_status` 推送

### 位置

[`app/services/trade_processor.py`](../app/services/trade_processor.py) 的 `_calculate_index()` 方法末尾（散户路径约 [L570](app/services/trade_processor.py#L570)，庄家路径约 [L461](app/services/trade_processor.py#L461)）。

### 广播内容

```python
await ws_manager.broadcast(mint, {
    "type": "user_status",
    "data": {
        "address": address,
        "status": state["status"],
        "status_source": state.get("status_source", "system"),
        "conditions": state.get("conditions", []),

```

## 四、完整时序流程

```
用户点击"开始"
  │
  ├─ startMonitor()
  │   ├─ fetchUsers()        ← 一次性拉全量用户（步骤二）
  │   │   └─ renderUserTable()
  │   │       └─ computeClusterSummary()  ← 自动计算簇组概览
  │   │
  │   └─ connectWS()         ← 建立 WebSocket
  │
  ▼
每笔 tx 到达
  │
  ├─ _calculate_index()
  │   ├─ get_trader_state_with_sig()  ← C002-C008 判定
  │   ├─ BUY/SELL 计算
  │   ├─ save_trader_state()          ← 写入 user:{address}
  │   │
  │   └─ ws_manager.broadcast("user_status", {...})  ← 推送
  │
  ▼
前端 WS onmessage
  │
  ├─ msg.type === "user_status"
  │   ├─ handleUserStatus()
  │   │   ├─ 更新交易表格行
  │   │   └─ upsertUserRow()
  │   │       └─ renderUserTable()
  │   │           └─ computeClusterSummary()  ← 同步刷新簇组概览
```

## 五、两条路径对比

| | 初始加载 | 实时更新 |
|------|----------|----------|
| 触发方式 | `startMonitor()` | 每笔 tx 的 `_calculate_index()` |
| 传输方式 | HTTP `GET` | WebSocket `user_status` |
| 数据范围 | 当前 mint 全量用户 | 单用户 |
| 性能 | SCAN 全部 `user:*` key | 无额外查询，直接推送 |
| 前端操作 | 覆盖整个 `userData` | 覆盖/新增单个 `userData[address]` |
