# /trade 页面用户列表功能设计

## 一、功能概述

在 `/trade` 实时交易页面下方新增**当前 mint 用户列表**，展示所有参与交易的地址及其状态信息。用户状态（新增/修改）通过 WebSocket 实时推送，支持排序和手动调整。

---

## 二、展示字段

| 列名 | 来源 | 说明 |
|------|------|------|
| **地址** | `user:{address}` | 显示前 4 位，**可点击**打开手动修改弹窗 |
| **状态** | `status` | `dealer` / `retail` / `unknown`，带颜色标签 |
| **来源** | `status_source` | `system`（系统判定）/ `manual`（手动锁定） |
| **簇组** | `cluster_name` | 所属簇组名（截断显示） |
| **簇组类型** | `cluster_type` | 从簇组 Redis 实时读取 |
| **条件** | `conditions` | 触发的检测条件列表，如 `C002,C006` |
| **持仓数量** | `holdingQty` | 当前持仓代币数量 |
| **持仓成本** | `holdingCost` | 持仓成本 (SOL) |

## 三、数据流

### 3.1 页面加载初始化

```
用户打开 /trade
  └─ 启动监控后 → GET /admin/api/users?mint={mint}
       └─ 扫描 Redis 所有 user:{address} 中带 {mint}_ 前缀 key 的记录
       └─ 返回用户数组 → 渲染列表
```

### 3.2 新交易 → 实时更新

```
tx_detail 到达
  └─ _calculate_index()
       └─ get_trader_state_with_sig()
            ├─ 新用户：C002-C006 判定 → 写 Redis
            └─ 已有用户：读 Redis + 同步簇组 → 写 Redis
       └─ save_trader_state()  ✅ 已保存
       └─ 广播 user_status (新增)  ← 新增广播
            └─ 前端收到 {type: "user_status"}
                 ├─ 已存在 → 更新行
                 └─ 不存在 → 新增行
```

### 3.3 管理员手动修改

```
管理员点击地址 → 弹窗选择状态
  └─ PUT /admin/api/users/{address}/status  {"status": "dealer"}
       └─ Redis: status=dealer, status_source=manual
       └─ 返回 JSON
       └─ 前端立即更新行：状态 + 来源
```

### 4.1 API 端点详情

**GET /admin/api/users?mint={mint}**

```json
{
  "users": [
    {
      "address": "GDzisw...",
```

```json
    "cluster_name": "GDzisw_BUY",
    "cluster_type": "retail",
```

## 六、实时性保证

| 场景 | 触发方式 | 延迟 |
|------|---------|------|
| 新用户首次交易 | WS `user_status` 广播 | 实时 |
| 已有用户新交易 | WS `user_status` 广播 | 实时 |
| 簇组类型变更 | 下一笔交易 WS `user_status` 广播 | 近实时 |
| 管理员手动修改 | PUT API 返回 → 前端更新 | 实时 |
| 页面首次加载 | HTTP GET `/admin/api/users` | 请求级 |

**所有 `user:{address}` 的变更都能通过 WS 推送实时反映到前端用户列表。**
